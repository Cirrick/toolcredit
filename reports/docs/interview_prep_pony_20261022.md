## 1. 30 秒电梯陈述

> 我做的是多轮工具调用大模型 RL 里的**信用分配**问题。任务是数学推理 + Python 解释器，模型是 Qwen3-1.7B，框架 veRL + GRPO，单卡 GH200。
> 标准 GRPO 只在轨迹末尾给一个对错奖励，再把同一个优势广播给每一轮——有用的工具调用和报错的调用拿到一样的梯度。
> 我先搭了完整管线（沙箱、verifier、蒸馏 + 拒绝采样做 SFT 冷启动），GRPO 把 MATH500 从 59.4% 提到 76.6%；
> 然后做轮级信用分配，发现它早期学得更快但终点没提升，还诱发了严重的工具过度调用。
> 我把根因定位到"修正项不守恒、等价于隐式稠密奖励"，用守恒版本做反事实验证，过度调用消失。
> 后面又补了无工具因果对照和 DAPO 动态采样的算力归一化消融。核心收获是：**在 RL 里，信号设计错了，模型会非常高效地钻空子**，
> 以及如何用预注册 + 配对统计把"漂亮数字"和真实效果分开。

## 2. 项目骨架（必须背熟的数字）

**设置**：Qwen3-1.7B｜veRL 0.8.0 + SGLang async rollout + FSDP｜单卡 GH200（aarch64，无 docker）
GRPO：64 prompt × 8 rollout，lr 1e-6，KL 进 loss（0.001，low_var_kl=k3），clip 0.2/0.28（clip-higher），token-mean，
T=1.0，prompt 1024 / 累计 response 3072 token，**最多 4 次工具调用 / 5 轮 assistant 回复**，200 step。
奖励：`1.0·答对(严格 \boxed{}) + 0.1·格式`——本质是 sparse outcome reward。

**数据**：MATH train 7500 → 13-gram + 精确匹配去污染剔 216 → 取 L3–5 共 5403 → 留 200 held-out → RL/SFT 池 5203。
**评测**：FULL760 = MATH500 + AIME24(30) + AIME25(30) + GSM8K(200)，greedy + 4 采样；逐题配对、10k 次分层 bootstrap CI。

## 3. 两分钟主线（讲故事的顺序）

1. **问题**：多轮工具调用的轨迹只有终点奖励，GRPO 广播给所有轮 → 信用分配粗糙。和多智能体里"团队奖励怎么分给个体"（QMIX）同构。
2. **先确认前提**：零样本给工具反而掉 10pt；机制分解说明是执行不可靠（报错、烧光调用预算截断），不是工具没用 → 需要 SFT 冷启动。
3. **把地基打牢**：沙箱、verifier 审计、loss mask 测试；SFT 数据通过真实 veRL AgentLoop **重放**生成 token/mask，保证 SFT 与 RL rollout 编码一致。
4. **基线**：E3 GRPO 训稳，+17.2pt（MATH500）。
5. **核心实验**：轮级信用 E5——机制审计证明修正确实生效（10.2 万轨迹、36 万 turn、方向零违约），但出现 over-calling。
6. **诊断**：修正项不守恒 → ① 同位置比较让"不调用/早停"被罚；② 轨迹净修正随调用数单调；③ 约一半组内零方差的组里它是唯一的策略梯度来源 → 等价于隐式奖励"多调用"。
7. **反事实**：守恒版 v2，过度调用消失、准确率不掉，但也没检出提升（作用面只有 4–10% 轨迹，≤4 轮 horizon 近似 bandit）。
8. **补因果空洞**：无工具对照 → RL 的提升主要是模型推理变强 + 不再被工具拖累，工具本身边际价值不显著（只在 L4/L5 难题有正贡献）。
9. **效率**：DAPO 动态采样，按 step 看赢、按 rollout 算力看持平——"论文只画了一条 x 轴"。

## 4. 项目深挖高频追问

**Q: 为什么选 GRPO 不用 PPO？**
critic-free，用组内相对奖励当 baseline 省掉 value model（显存和训练不稳定）；sparse outcome 场景自然。代价是每个 prompt 要采 n 条。

**Q: GRPO 优势公式？有什么问题？**
`A_i = (r_i − mean(r)) / std(r)`，广播给该轨迹所有 token。问题：组内全对/全错时 A=0 无梯度（DAPO 动态采样解决）；
除 std 引入难度偏置、按长度归一化引入长度偏置（Dr. GRPO）。我用的是 token-mean 聚合，保留了除 std。

**Q: 零方差组为什么危害大？**
① rollout 白采；② token-mean 下这些序列不贡献分子但占分母，相当于悄悄衰减学习率；③ 有效 batch 随训练漂移。
注意：零方差时只是 policy-gradient 项为 0，KL loss 仍有梯度。

**Q: 轮级信用具体怎么算的？s_t 是什么？**
s_t=1 当且仅当该轮工具调用执行成功、且返回结果在后续 assistant 文本中被引用（启发式 adoption，不是 PRM）。
v1：`s̄_t` 取同组同位置均值；v2：轨迹内 token 加权均值，`Σ c_t·n_t = 0`，逐轨迹守恒残差 ≤1e-13。
learning-free：不训 critic/PRM、不增加采样。

**Q: 这算 reward hacking 吗？**
要分清：E5 没改 outcome reward、reward 也没异常上涨，严格说是 **credit-signal / proxy gaming**——修正项不守恒，等价于在 advantage 里加了一个隐式稠密奖励，策略最大化了它。
**E4 才是干净的 reward hacking**：显式 exec bonus 下，常量执行（print(1)）、重复失败调用、调用后忽略结果。
不说模型"有意作弊"。

**Q: 守恒为什么能修好？和 potential-based shaping 什么关系？**
直觉：守恒 = 每条轨迹总信用和 E3 一样，只在轮次之间重新分配，不能靠"多调用"整体加分。和 Ng 的 potential-based shaping 思路相通（不改变最优策略的 shaping），
但我的 v2 不是那个定理的严格实例，不要说"证明了最优策略不变"。另外 v2 同时改了守恒、门控、打分条件，**不能把行为改善单独归因于守恒一项**。

**Q: 轮级信用最终没提升，为什么？**
① 作用面小：只有同轨迹 ≥2 次可区分调用时非零，exposure 10.4%→4.2%；② 策略被训成"少调用"，自己缩小作用面；③ ≤4 轮 horizon 下近似 bandit，组内 outcome 方差已经够用；④ s_t 是启发式代理。
值得做的条件：更长 horizon、真实 agent 状态、能区分信息增益和复述的步骤信号。

**Q: SFT 6,000 条够吗？算蒸馏吗？算 OPD 吗？**
冷启动目标是接口可靠性，不是教数学。比较过 2.5k vs 6k，工具错误率 22%→19%，未证明饱和。
是序列级/轨迹蒸馏（教师生成 + 拒绝采样），没有用教师 logits；**不是 OPD**（OPD 是学生自己采样、教师逐 token 给 reverse-KL 稠密信号）。
拒绝采样让教师准确率只影响产量、不影响数据正确性。

**Q: loss mask 怎么做的？不 mask 会怎样？**
工具返回 token 保留在上下文（attention 可见）但 loss mask=0——loss mask ≠ attention mask。
单测用真 tokenizer + 真 hermes parser + 真工具，只 mock LLM server，驱动 veRL `ToolAgentLoop` 状态机断言 mask。
E6 故意不 mask：4.66% loss token 来自环境，80 step 内没崩，有少量伪造 `<tool_response>`——结论是"必须 token 级审计"，不是"mask 无所谓"。

**Q: 为什么最多 4 次调用 / 3072 token？**
工程折中，不是搜索出的最优。事后复核：教师轨迹 P95≈2050、P99≈3079 token；E3 greedy 只有 10/760 用满 4 次。
E3 截断失败 70 条同时放宽 token(3072→6144) 和调用(4→6)，只 16 条转正确，30/38 持续截断的是语言循环 → 加预算不是方向。

**Q: 你的 +12.76pt 是学会用工具还是模型变强？**
做了无工具对照：同配方去掉工具，终点打平。分解：6.05（不再被工具拖累）+ 4.74（推理变强，CI [2.11,7.50] 显著，留在权重里）+ 1.97（工具推理时边际价值，不显著）。工具只在 MATH L4/L5 有 +3~+7pt。

**Q: DAPO 动态采样有用吗？**
按训练 step 看 E7 终点 +5.13pt；按累计 rollout 算力对齐（E7 step 95 = E3 全程 102,400 条轨迹）只差 −0.39pt。
"等算力无免费午餐，多算力换终点"；缺 E3 同预算臂，不能说过滤本身提升 5pt。成本随策略变准单调上升（每步补采样批数 2.0→3.06）。
为什么不上 DAPO 四件套：clip-higher 和 token-level loss 已在基线里；单因子消融才能归因；overlong shaping 改 reward 属 E4；去 KL 信息量低。

**Q: 统计上怎么保证结论可信？**
预注册判读矩阵（先写情形 A/B/C/D 再看结果）；评测协议 hash 冻结、版本化；同题配对 + 10k 次 source 分层题级 bootstrap；resolved-config diff 精确等于预注册路径数（单因子）；
局限：单 seed，bootstrap 只衡量题目抽样方差、不衡量训练 seed 方差。

**Q: 遇到最难的工程问题？**
六条 200-step run 都在 5–9 小时后被"pod 中断"。排查：cgroup 128GiB + `memory.oom.group=1` 的组级 OOM → 关 FSDP CPU offload 基线 49→25GiB 但斜率不变 →
memwatch 按进程读 `/proc/<pid>/smaps_rollup` 的 Pss_Anon，按重启分段拟合（跨段混拟会给出 0.038 的假斜率，差一个量级）→ 单个 `ray::WorkerDict`（actor+ref 共置的 FSDP worker）0.52 GiB/step 占 93.4%；
增长跟有效 update 次数挂钩而非 rollout 数。只定位到进程、没定位到代码行；运行纪律改为每 50 step 计划性 checkpoint 重启。

**Q: 为什么用 veRL 不用 TRL？为什么 Qwen3-1.7B？**
veRL 原生 multi-turn + tool、SGLang/vLLM rollout 吞吐高、接近工业栈。1.7B：单卡可跑 200 step × 多臂对照；有足够 headroom（CoT L4 0.75/L5 0.43）和组内方差。

## 5. 基础知识题速查

- **PPO clip**：`min(ρA, clip(ρ,1−ε,1+ε)A)`，ρ=π_θ/π_old。**clip-higher**（ε_low 0.2 / ε_high 0.28）：给低概率 token 更大上调空间，防熵坍缩。
- **KL 估计**：k1=log(π/π_ref) 无偏高方差可负；k3=(r−1)−log r，r=π_ref/π_θ，无偏、非负、低方差（veRL `low_var_kl`）。KL 放 loss 而非 reward。
- **GAE**：`A_t = Σ(γλ)^l δ_{t+l}`，δ_t=r_t+γV(s_{t+1})−V(s_t)；λ 权衡偏差/方差。GRPO 没 critic 所以没 GAE。
- **token-mean vs seq-mean**：token-mean 长序列权重大，避免"错答越长每 token 罚越轻"的长度偏置。
- **熵坍缩信号**：entropy 单调降到很低、pass@k 不涨；对策 clip-higher、升温、熵正则。我的 E3 entropy 0.19–0.32 健康。
- **reward hacking 排查信号**：训练 reward 涨、held-out pass@1 不动 → 立即抽轨迹人检。
- **on/off-policy**：GRPO 每步用当前 snapshot 采样，mini-batch 多次更新后略 off-policy，靠 importance ratio + clip 修正。
- **LoRA**：低秩 ΔW=BA，只训 A/B；我 SFT 用 LoRA r32/α64，RL 是全参（FSDP）。
- **veRL 架构**：Ray 单控制器；actor/ref FSDP、rollout 用 SGLang、AgentLoop 管多轮工具交互、reward 函数打分 → 优势 → 更新。

## 6. 口径红线（别说错）

- ❌ "轮级信用分配提升了准确率" → ✅ 终点未检出差异，v1 早期更快，v2 消除了 over-calling。
- ❌ "守恒性被因果证明" → ✅ v2 同时改了守恒、门控、打分条件，联合效果。
- ❌ "动态采样提升 5 个点" → ✅ 等算力持平，2.53× rollout 换来 +5.13pt，缺同预算对照。
- ❌ "工具没用" → ✅ 该规模/该任务下净贡献不显著，难题 L4/L5 有正贡献。
- ❌ "6000 道题" → ✅ 6,056 条轨迹，覆盖 3,716 题。
- ❌ "当初按 P99 选的 3072" → ✅ 工程折中，事后复核支持。
- 34%→19%（raw→SFT 探针）、59.4%→76.6%（MATH500）、92.9%→0.8%（FULL760 v1→v2）**三个数字来自三个不同对照**，别混。
- 单 seed 是最大局限，主动承认。

## 7. 迁移到小马智行（自动驾驶）的连接点

（以下是项目方法论到自驾问题的类比，不是项目做过的实验；公司具体技术细节面试前自行核实。）

| 本项目 | 自动驾驶对应 |
|---|---|
| 轨迹末尾 sparse reward 如何分到每一轮 | 长时域驾驶中碰撞/接管等稀疏事件如何归因到具体决策时刻（时序信用分配） |
| 非守恒 shaping → over-calling | 奖励设计漏洞 → 过度保守（为避免碰撞罚分停车不走）、为舒适度奖励"刷"平滑轨迹等 specification gaming |
| 守恒再分配 / potential-based shaping | 加稠密奖励时要保证不改变最优策略，否则优化目标被偷换 |
| 行为指标比准确率更早暴露问题（4-call 92.9%） | 闭环评测不能只看成功率，要看接管率、急刹、违规等行为分布 |
| 等算力对比（两条 x 轴） | 在仿真/世界模型里做 RL 时，按仿真里程/算力而不是迭代步数比较方法 |
| 预注册 + 配对 bootstrap + 单因子 config diff | 场景库上的回归测试、A/B 对比要配对、控制变量 |
| 冻结评测协议、hash、版本化 | 仿真评测集/指标版本管理，避免"评测漂移" |
| 训练基础设施排障（cgroup OOM、进程级内存拟合） | 大规模训练/仿真集群的稳定性 |

可能被问："如果在自驾上做 RL，你最担心什么？" → 奖励设计的 specification gaming（我亲眼看到模型在一个隐式奖励上几十步内把行为推到极端）、
仿真到真实的分布偏移、评测要闭环且按算力归一化、安全约束应是硬约束而非可被抵消的 shaping 项。

## 9. 最可能的 10 个问题与口述版回答

1. **介绍项目**：问题（结果奖励广播给每轮）→ 管线 → 60.5→73.3 → 轮级信用的 over-calling 与守恒修正 → 无工具对照、DAPO 消融 → 收获是"信号有漏洞就会被钻空子"。
2. **GRPO 原理 / 为什么不用 PPO**：同题 8 条采样，A=(r−mean)/std 广播给所有 token；PPO clip（0.2/0.28 clip-higher）+ KL 进 loss（0.001，k3）；省 critic、单卡、稀疏结果奖励天然适配；代价是多采样与零方差组。
3. **多轮与单轮的区别 / loss mask**：轨迹里交错着环境 token，必须 mask 出 loss 但保留 attention；单测驱动真实 ToolAgentLoop；SFT 用重放保证编码一致；E6 不 mask：4.66% loss token 来自环境，80 步未崩但出现伪造 tool_response。
4. **为什么 SFT 冷启动 / 数据怎么来**：零样本工具 −10pt（报错、无状态沙箱、烧光预算）；Qwen3-8B × 5,203 题 × 2 条 → 五条件拒绝采样 6,056 条（含 797 恢复）；LoRA vs full SFT：full 准确率略高但工具错误率更差，保留 LoRA；34%→19%。
5. **+12.8pt 来自哪里**：无工具对照 −0.92pt 持平；6.05 + 4.74 + 1.97 分解；工具只在 L4/L5 有正贡献。
6. **轮级信用怎么设计**：A_turn = A_traj + 0.5(s_t − s̄_t)；s_t = 执行成功且被后文引用；不训 critic、不加采样；10.2 万轨迹机制审计零违约；早期 AUC +3pt、终点持平。
7. **过度调用怎么发现 / 根因 / 算不算 reward hacking**：4-call 1.3%→92.9%、截断 100%；三条根因（同位置比较罚早停、净修正随调用数单调、零方差组里是唯一梯度）；proxy gaming，E4 才是显式 reward hacking。
8. **怎么修 / 为什么没提准确率**：轨迹内 token 加权零和 + 零方差门控 + 重复/boxed 后调用置 0；相对 v1 大幅下降、相对 E3 小幅；.741 vs .733 不显著；作用面 4–10%、近似 bandit、启发式信号；v2 多处同时改，不单独归因守恒。
9. **DAPO 动态采样 / 78.4% 公平吗**：丢零方差组、同 snapshot 补采样；相同步数 +5.13pt 但 2.53× rollout；等算力持平；成本随训练上升（34.5%→61.4%，2.0→3.06 批）；为何不上四件套。
10. **最大的工程困难**：pod 中断 → cgroup 组级 OOM → 关 offload 降基线不降斜率 → 按进程 Pss_Anon 分段拟合 → ray::WorkerDict 93.4%；每 50 步计划性重启。

（附加）**迁移到自动驾驶**：稀疏事件的时序归因、奖励漏洞导致的过度保守、闭环行为指标、按算力/里程比较方法。
