\section{Cross-Family Comparison and a Selection Guide}\label{sec:comparison}

No family dominates: each buys better credit by assuming something about the environment or by spending compute. Table~\ref{tab:comparison} lays out these trade-offs as our qualitative synthesis of Section~\ref{sec:taxonomy} (not measured quantities), and the guide below matches them to environment properties.

\paragraph{Selection guide by environment property}
\begin{itemize}
  \item \textbf{Stateless or prefix-replayable} (pure text, math with stateless Python calls). Replaying the token prefix ``resets'' the state, so branching estimators (b) give cheap, unbiased turn values. If a gold answer exists, gold-likelihood turn rewards (d) cost one forward pass per turn. Key-token selection (e) is nearly free and can be added to either. Anchor grouping (c) helps little here, because exact states rarely recur.
  \item \textbf{Stateful but snapshottable} (SWE, terminal, web and memory sandboxes). Branching still works if snapshot fidelity holds~\citep{bpo2026branching}, but fork latency limits throughput~\citep{deltabox2026}. LoGo-GRPO's rerollouts from a shared memory state are an instance of this regime (Section~\ref{sec:memory}).
  \item \textbf{Non-resettable} (live web, real users, irreversible actions). Only reset-free methods remain: turn-level or privileged critics (d, f) and hindsight critics (e). These signals have no ground truth, so audit them against replay where possible~\citep{zhang2026credit}.
  \item \textbf{Horizon.} With few turns, dilution is mild and turn-level methods have little room to help (Section~\ref{sec:toolcredit}). As the horizon lengthens, the case for denser credit strengthens, and so does the danger of gameable per-turn signals.
  \item \textbf{Verifiable versus judged reward.} With a verifier, keep the outcome reward dominant and treat dense credit as shaping. With only a judge, the judge's bias reaches every turn, and the hacking risks of Section~\ref{sec:tax-failures} grow.
\end{itemize}

\paragraph{Two cross-cutting observations}
First, \emph{infrastructure and credit assignment are converging}: tree rollouts, sibling baselines and sandbox snapshot/fork runtimes are being co-designed~\citep{ji2025tree,bpo2026branching,deltabox2026,crab2026}, so rollout branching \emph{is} the credit estimator, now practical where it used to be prohibitive. Second, \emph{compute-matched comparisons are rare}: most families are evaluated against GRPO at an equal number of trajectories, not at equal tokens, tool calls or effective samples, and the first replay audit finds common credit signals no better than shuffled controls (Section~\ref{sec:tax-failures}). Credit quality has rarely been measured directly, independent of downstream accuracy, and a protocol for doing so is still missing.
