\section{Cross-Family Comparison and a Selection Guide}\label{sec:comparison}

No family dominates. Each one buys better credit by assuming something about the environment or by spending compute somewhere. Table~\ref{tab:comparison} lays out these trade-offs, and the guide below matches them to environment properties. The entries are our qualitative synthesis of the evidence in Section~\ref{sec:taxonomy}, not measured quantities.

\paragraph{Selection guide by environment property}
\begin{itemize}
  \item \textbf{Stateless or prefix-replayable} (pure text, math with stateless Python calls). A state can be ``reset'' by replaying the token prefix, so branching from intermediate turns is cheap. Branching estimators (b) give unbiased turn values. If a gold answer exists, gold-likelihood turn rewards (d) cost one forward pass per turn. Key-token selection (e) is nearly free and can be added to either. Anchor grouping (c) helps little here, because exact states rarely recur.
  \item \textbf{Stateful but snapshottable} (SWE, terminal, web and memory sandboxes). Branching still works, provided snapshot fidelity holds~\citep{bpo2026branching}. Fork latency then limits training throughput~\citep{deltabox2026}. LoGo-GRPO's rerollouts from a shared memory state are an instance of this regime (Section~\ref{sec:memory}).
  \item \textbf{Non-resettable} (live web, real users, irreversible actions). Only methods that need no reset remain. Use turn-level or privileged critics (d, f) or hindsight critics (e). These signals have no ground truth, so audit them against replay where possible~\citep{zhang2026credit}.
  \item \textbf{Horizon.} With a few turns, outcome-only GRPO already resolves much of the credit, and turn-level methods have little room to help. Dilution grows with the number of turns, so the case for denser credit gets stronger as the horizon lengthens. For the same reason, per-turn signals that can be gamed become more dangerous.
  \item \textbf{Verifiable versus judged reward.} With a verifier, keep the outcome reward dominant and treat dense credit as shaping. With only a judge, the judge's bias reaches every turn, and the hacking risks of Section~\ref{sec:tax-failures} grow.
\end{itemize}

\paragraph{Two cross-cutting observations}
First, \emph{infrastructure and credit assignment are converging}. Tree rollouts, sibling baselines and sandbox snapshot/fork runtimes are being co-designed~\citep{ji2025tree,bpo2026branching,deltabox2026,crab2026}: rollout branching \emph{is} the credit estimator. A 2026 cluster of checkpoint/restore systems has made branching practical in environments where it used to be prohibitive. Second, \emph{compute-matched comparisons are rare}. Most families are evaluated against GRPO at an equal number of trajectories, not at equal tokens, tool calls or effective samples. The first replay-based audits find that commonly used credit signals are no better than shuffled controls, and that differences between methods are confounded by training dose~\citep{zhang2026credit}\unverified. Credit quality has rarely been measured directly, independent of downstream accuracy, and a protocol for doing so is still missing.
