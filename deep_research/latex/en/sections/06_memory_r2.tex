\section{Memory-Augmented Agents and Memory-R2: A Close Reading}\label{sec:memory}

Long-term memory gives the cleanest example of the credit problem for agents. A policy decides what to write, rewrite or delete, and it learns whether that decision was good only when a question arrives, often many sessions later. This section describes the memory landscape, reads Memory-R2~\citep{yan2026memory} closely, and lists what its evidence does and does not establish.
\emph{Source caveat.} We could not access the full text or code of Memory-R2. Details beyond its abstract come from excerpts of the arXiv HTML and the GitHub README, and we mark them \unverified. The marker also covers IDs and facts that come from prior knowledge.

\subsection{Memory as an action space}

\paragraph{Non-RL memory systems}
The first generation of memory systems used fixed pipelines. MemGPT pages content between the context window and external storage through function calls~\citep{packer2023memgpt}. A-Mem keeps Zettelkasten-style linked notes~\citep{xu2025amem}. Mem0 extracts facts and applies ADD/UPDATE/DELETE/NOOP to a vector store~\citep{chhikara2025mem0}. Zep uses a temporal knowledge graph~\citep{rasmussen2025zep}\unverified. In all of these a prompted LLM chooses the operation, and no component learns from whether a stored fact later helped. Even the reported numbers are disputed: Zep reran its own system on LoCoMo and got 75.14\%, against the 65.99\% that Mem0 reported for it. Zep is an interested party in this dispute.

\paragraph{RL for memory and context management}
RL work trains the write and read policy directly (Table~\ref{tab:mem-rl}). One family manages the context of a single long task, where the agent rewrites its own working memory. The other builds persistent memory across sessions. In 2026, credit for memory writes became an explicit research topic.

\paragraph{Why memory is a hard credit-assignment case}
A memory write works like a deposit that may or may not be withdrawn much later. Several things make the bookkeeping hard:
(i)~\emph{Delay.} A fact written in session~3 may be needed in session~30.
(ii)~\emph{Counterfactual value.} A DELETE or NOOP is useful or harmful only if some future question would have used the fact.
(iii)~\emph{Interaction.} The value of an UPDATE depends on the UPDATEs that follow it.
(iv)~\emph{Environment noise.} The retriever and answer agent are part of the environment, so the reward also reflects their errors.
(v)~\emph{Sparse coverage.} Most stored facts are never queried, so most writes receive no signal at all.
On top of these comes a structural problem we call \emph{same group, different intermediate state}. GRPO (\S\ref{sec:background}) compares $n$ rollouts on one conversation as if they faced the same task. Suppose rollout~A deleted a fact in session~3 and rollout~B kept it. By session~20 the two rollouts are acting on different memory banks, which means they are in different environments. The group mean is a valid baseline only for the shared start state. As a result, a good write made late in a rollout that was already damaged can receive a negative advantage.

\paragraph{Benchmarks and their problems}
LoCoMo~\citep{maharana2024evaluating} is the training and evaluation set for Memory-R1/R2. It contains about ten long conversations\unverified, which fit in a modern context window, so a full-context baseline is necessary. A non-peer-reviewed audit found score-corrupting errors in 99 of 1{,}540 questions (6.4\%). The same audit reports that an LLM judge accepts up to 63\% of deliberately wrong answers~\citep{penfieldlocomo}. In addition, 444 of the 446 adversarial questions have empty gold answers~\citep{atant2026}. LongMemEval~\citep{wu2024longmemeval} has 500 questions covering temporal reasoning, multi-session reasoning, knowledge updates and preferences. MemoryAgentBench~\citep{hu2025evaluating} feeds information incrementally and tests four competencies: retrieval, test-time learning, long-range understanding and selective forgetting. Some 2026 work questions whether a single score is meaningful for memory that changes over time~\citep{onescore2026}.

\subsection{Memory-R1 in brief}
Memory-R1~\citep{yan2025memory} (ACL~2026) trains two agents with outcome RL, using PPO or GRPO; GRPO is generally the better of the two. The \emph{Memory Manager} chooses ADD/UPDATE/DELETE/NOOP for each extracted fact. The \emph{Answer Agent} filters the retrieved memories and then answers. Training uses only 152 LoCoMo QA pairs. Our reading of the v1 table puts overall F1 at 31.41$\to$45.20 for LLaMA-3.1-8B and 38.44$\to$46.70 for Qwen-2.5-7B, each against Mem0\unverified. The headline relative gains differ across arXiv versions because the baselines differ, so it is safer to quote absolute scores with the version. The manager is rewarded by whether the answer agent is then correct\unverified. This gives each update a short effective horizon, which is exactly the assumption Memory-R2 drops.

\subsection{Memory-R2}

\paragraph{Problem setup}
Memory-R2 (arXiv 2605.21768; NeurIPS~2026 according to the authors' announcements\unverified) changes Memory-R1 in four ways~\citep{yan2026memory}:
\begin{itemize}
\item A fact \emph{extractor} and a memory \emph{manager} share one Qwen2.5-7B-Instruct policy and differ only in their role prompts. The manager issues INSERT/UPDATE/DELETE\unverified; whether NOOP survives is unclear.
\item The answer agent is frozen (GPT-OSS-120B)\unverified, so credit is purely on the write side.
\item The reward is the downstream QA performance, computed once per trajectory. The exact metric is not given in our sources.
\item The training horizon follows a curriculum of 8$\to$16$\to$32 sessions, and the 32-session checkpoints are evaluated zero-shot out of distribution.
\end{itemize}
Training uses only two LoCoMo conversations\unverified, and results are averaged over three runs\unverified.

\paragraph{The fairness argument}
The paper argues that once rollouts write, update or delete different memories, ``they no longer share the same intermediate memory state, making trajectory-level comparisons fundamentally unfair''\unverified. This is the same-group, different-state problem described above. Stated in baseline terms, GRPO's group mean estimates $V(m_0)$, but a decision in session $u$ needs the baseline $V(m^{(i)}_{u-1})$, and that value differs across rollouts.

\paragraph{LoGo-GRPO (our schematic reading)}
Let $\tau_1,\dots,\tau_n$ be global rollouts on one conversation with $S$ sessions. Let $m^{(i)}_{s}$ be the memory bank of rollout $i$ after session $s$, and let $R(\tau_i)$ be the QA reward of the frozen answer agent. The \emph{global} advantage is standard trajectory-level GRPO:
\begin{equation}
A^{\mathrm{glob}}_i=\frac{R(\tau_i)-\operatorname{mean}_{j}R(\tau_j)}{\operatorname{std}_{j}R(\tau_j)}.
\end{equation}
For a sampled session $u$, the method snapshots $m^{(i)}_{u-1}$ and re-rolls session $u$ $K$ times from that identical state, producing rerollouts $\tau^{(i,u)}_1,\dots,\tau^{(i,u)}_K$ with rewards $r_k$. The \emph{local} advantage is then group-normalized within these siblings:
\begin{equation}
A^{\mathrm{loc}}_{i,u,k}=\frac{r_k-\operatorname{mean}_{l}r_l}{\operatorname{std}_{l}r_l},\qquad
A_{i,u}=A^{\mathrm{glob}}_i+\lambda\,A^{\mathrm{loc}}_{i,u}.
\end{equation}
$A_{i,u}$ is applied to every token of step $u$ inside a clipped GRPO surrogate, matching the paper's description that ``each step's advantage is \ldots\ the token-level advantage for all tokens in step $u$''\unverified. The local term is a Monte-Carlo estimate of a state-conditioned baseline, in the spirit of the methods in \S\ref{sec:taxonomy}.
Our sources do \emph{not} specify:
\begin{itemize}
\item how the two terms are combined (we write $\lambda$ for convenience);
\item the group sizes $n$ and $K$;
\item how many sessions are snapshotted per trajectory;
\item whether $r_k$ comes from completing the remaining sessions or from a session-local proxy;
\item the wall-clock or GPU overhead relative to GRPO.
\end{itemize}
If rerollouts do run to the end of the horizon, the cost per trajectory grows by about $\sum_{u\in\mathcal U}K(S-u+1)$ session executions, where $\mathcal U$ is the set of snapshotted sessions. This estimate is ours.

\paragraph{Results}
Table~\ref{tab:memr2} summarizes the reported numbers. In a setting where all methods share the same backbone, Memory-R2 reports the best F1 and BLEU-1 among training-free and trained baselines, including MEM1, MemAgent and Memory-R1. Most of the gain comes from training the memory module, not the answer agent. Swapping LoGo-GRPO for plain GRPO costs about 3~F1. The authors also report zero-shot gains over the base model on LongMemEval, MSC-Self-Instruct and MemBench~\citep{tan2025membench}, and transfer from 3B to 7B, with the largest gains on the smaller model\unverified.

\paragraph{A convergent design}
Mem-T, tree-based CA and LoGo-GRPO all obtain per-step baselines by \emph{branching from a shared prefix or state}, the same idea as VinePPO, SPO and Tree-GRPO in reasoning RL (\S\ref{sec:taxonomy}). What Memory-R2 adds is branching at the level of sessions and memory states while keeping a global end-to-end term.

\subsection{Critical assessment}
We pose the following as open questions rather than verdicts. Several of them may be answered in the full paper, which we could not read.
\begin{itemize}
\item \textbf{Resettability.} LoGo-GRPO assumes the memory bank can be snapshotted and restored exactly. That holds for a text store but not for environments with side effects such as email, filesystems or real web interactions. How should a fair local baseline be built when exact reset is impossible, \eg with learned state abstractions or GiGPO-style anchors (\S\ref{sec:taxonomy})?
\item \textbf{Matched compute.} The 3-point gain over GRPO comes with an unreported number of extra rollouts. Extra rollouts alone can explain gains of this size. In our own experiments (\S\ref{sec:toolcredit}), a variant that used 2.53$\times$ the rollouts of its GRPO baseline gained +5.1 points at its endpoint but showed no significant gain at matched compute. The decisive missing baseline is GRPO with the same number of session executions and tokens, or with $n$ raised until the budgets are equal.
\item \textbf{Scale of the evidence.} Training on two conversations and testing on a ten-conversation benchmark means seeds do not substitute for conversation diversity. Confidence intervals should be computed at the conversation level. LoCoMo's answer-key errors and its lack of knowledge-update questions add noise of roughly the same size as a 3-point effect.
\item \textbf{Judge sensitivity.} Uni-Mem re-evaluated released RL-memory checkpoints with a Mem0-aligned judge prompt and reports outperforming the strongest of them~\citep{unimem2026}. This suggests that J scores are not comparable across papers.
\item \textbf{A stronger evaluation.} It would include:
  \begin{itemize}
  \item a rollout-matched GRPO baseline and a full-context baseline;
  \item LongMemEval and MemoryAgentBench as primary benchmarks, reported by category;
  \item several judges and conversation-level confidence intervals;
  \item a measured reduction in advantage variance, showing that the local term actually fixes the problem it targets.
  \end{itemize}
\end{itemize}

\paragraph{The authors' research direction}
Memory-R1 and Memory-R2 come from Sikuan Yan with Volker Tresp and Yunpu Ma, whose group is at LMU Munich/MCML\unverified, with industrial coauthors on Memory-R2. The group's 2026 papers point toward \emph{self-improving agents}. These include memory RL; reasoning compression through mixed-policy distillation~\citep{yang2026reasoning}; and recursive self-improvement through two-timescale meta-skill evolution on a frozen backbone~\citep{wang2026metaskill}. Ideas that combine memory credit with skill or experience evolution therefore sit close to this group's interests (\S\ref{sec:agenda}).
