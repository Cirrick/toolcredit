\section{Memory-Augmented Agents and Memory-R2: A Close Reading}\label{sec:memory}

Long-term memory is the cleanest example of the agent credit problem: a policy decides what to write, rewrite or delete, and learns whether that was good only when a question arrives, often many sessions later. We map the landscape, read Memory-R2~\citep{yan2026memory} closely, and ask what its evidence establishes.
\emph{Source caveat.} We could not access the full text or code of Memory-R2; details beyond its abstract come from excerpts of the arXiv HTML and the GitHub README and are marked \unverified, as are IDs and facts from prior knowledge.

\subsection{Memory as an action space}

\paragraph{Non-RL memory systems}
The first generation used fixed pipelines in which a prompted LLM chooses each operation: MemGPT pages content between context and external storage~\citep{packer2023memgpt}, A-Mem keeps linked notes~\citep{xu2025amem}, Mem0 applies ADD\slash UPDATE\slash DELETE\slash NOOP to a vector store~\citep{chhikara2025mem0}, and Zep uses a temporal knowledge graph~\citep{rasmussen2025zep}\unverified. Nothing learns from whether a stored fact later helped. Even reported numbers are disputed: Zep reran its own system on LoCoMo at 75.14\% against the 65.99\% Mem0 reported for it~\citep{zepmem0} (Zep is an interested party).

\paragraph{RL for memory and context management}
RL work trains the write/read policy directly (Table~\ref{tab:mem-rl}), either for the working memory of one long task or for persistent memory across sessions. In 2026, credit for memory writes became an explicit research topic.

\paragraph{Why memory is a hard credit-assignment case}
A memory write is a deposit that may or may not be withdrawn much later. (i)~\emph{Delay:} a fact written in session~3 may be needed in session~30. (ii)~\emph{Counterfactual value:} a DELETE or NOOP matters only if some future question would have used the fact. (iii)~\emph{Interaction:} an UPDATE's value depends on the UPDATEs that follow. (iv)~\emph{Environment noise:} the retriever and answer agent are part of the environment, so the reward also reflects their errors. (v)~\emph{Sparse coverage:} most stored facts are never queried, so most writes get no signal.
On top of these sits a structural problem we call \emph{same group, different intermediate state}. GRPO compares $G$ rollouts on one conversation as if they faced the same task. If rollout~A deleted a fact in session~3 and rollout~B kept it, by session~20 they act on different memory banks, \ie in different environments. The group mean is a valid baseline only for the shared start state, so a good late write in an already-damaged rollout can receive a negative advantage.

\paragraph{Benchmarks and their problems}
LoCoMo~\citep{maharana2024evaluating}, the training and evaluation set of Memory-R1/R2, has about ten long conversations\unverified{} that fit in a modern context window, so a full-context baseline is necessary. A non-peer-reviewed audit found score-corrupting errors in 99 of 1{,}540 questions (6.4\%) and an LLM judge accepting up to 63\% of deliberately wrong answers~\citep{penfieldlocomo}; 444 of 446 adversarial questions have empty gold answers~\citep{atant2026}. LongMemEval~\citep{wu2024longmemeval} (500 questions on temporal and multi-session reasoning, knowledge updates and preferences) and MemoryAgentBench~\citep{hu2025evaluating} (incremental input; retrieval, test-time learning, long-range understanding, selective forgetting) are broader; some 2026 work questions whether a single score suffices for evolving memory~\citep{onescore2026}.

\subsection{Memory-R1 in brief}
Memory-R1~\citep{yan2025memory} (ACL~2026) trains, with outcome RL on only 152 LoCoMo QA pairs, a \emph{Memory Manager} choosing ADD\slash UPDATE\slash DELETE\slash NOOP per extracted fact and an \emph{Answer Agent} that filters retrieved memories (PPO or GRPO, GRPO generally better). Our reading of the v1 table gives overall F1 31.41$\to$45.20 (LLaMA-3.1-8B) and 38.44$\to$46.70 (Qwen-2.5-7B) against Mem0\unverified; relative gains differ across arXiv versions, so absolute scores with the version are safer to quote. The manager is rewarded by whether the answer agent is then correct\unverified, a short effective horizon per update, which is exactly the assumption Memory-R2 drops.

\subsection{Memory-R2}

\paragraph{Problem setup}
Memory-R2~\citep{yan2026memory}, reportedly accepted at NeurIPS~2026 according to the authors' announcements\unverified, changes Memory-R1 in four ways. (1)~A fact \emph{extractor} and a memory \emph{manager} share one Qwen2.5-7B-Instruct policy, differing only in role prompts; the manager issues INSERT\slash UPDATE\slash DELETE\unverified{} (whether NOOP survives is unclear). (2)~The answer agent (GPT-OSS-120B) is frozen\unverified, so credit is purely write-side. (3)~The reward is downstream QA performance, computed once per trajectory; the exact metric is not in our sources. (4)~The horizon follows a curriculum of 8$\to$16$\to$32 sessions, and 32-session checkpoints are evaluated zero-shot out of distribution. Training uses only two LoCoMo conversations\unverified, with results averaged over three runs\unverified.

\paragraph{The fairness argument}
Once rollouts write different memories, ``they no longer share the same intermediate memory state, making trajectory-level comparisons fundamentally unfair''\unverified: GRPO's group mean estimates $V(m_0)$, but a decision in session $u$ needs $V(m^{(i)}_{u-1})$, which differs across rollouts.

\paragraph{LoGo-GRPO (our schematic reading)}
Let $\tau_1,\dots,\tau_G$ be global rollouts on one conversation with $S$ sessions, $m^{(i)}_{s}$ the memory bank of rollout $i$ after session $s$, and $R(\tau_i)$ the frozen answer agent's QA reward. The \emph{global} advantage is standard trajectory-level GRPO:
\begin{equation}
A^{\mathrm{glob}}_i=\frac{R(\tau_i)-\operatorname{mean}_{j}R(\tau_j)}{\operatorname{std}_{j}R(\tau_j)}.
\end{equation}
For a sampled session $u$, snapshot $m^{(i)}_{u-1}$ and reroll session $u$ $K$ times from that identical state, giving rewards $r_1,\dots,r_K$. The \emph{local} advantage is normalized within these siblings:
\begin{equation}
A^{\mathrm{loc}}_{i,u,k}=\frac{r_k-\operatorname{mean}_{l}r_l}{\operatorname{std}_{l}r_l},\qquad
A_{i,u}=A^{\mathrm{glob}}_i+\lambda\,A^{\mathrm{loc}}_{i,u}.
\end{equation}
$A_{i,u}$ is applied to every token of step $u$ inside a clipped GRPO surrogate, matching the paper's description that ``each step's advantage is \ldots\ the token-level advantage for all tokens in step $u$''\unverified. The local term is a Monte-Carlo estimate of a state-conditioned baseline, as in family~(b) of Section~\ref{sec:tax-mc}.
Our sources do \emph{not} specify how the two terms are combined ($\lambda$ is our notation), the group sizes $G$ and $K$, how many sessions are snapshotted per trajectory, whether $r_k$ comes from completing the remaining sessions or from a session-local proxy, or the overhead relative to GRPO. If rerollouts run to the end of the horizon, each snapshotted trajectory costs about $\sum_{u\in\mathcal U}K(S-u+1)$ extra session executions ($\mathcal U$: snapshotted sessions); this estimate is ours.

\paragraph{Results}
In a backbone-controlled comparison, Memory-R2 reports the best F1 and BLEU-1 among training-free and trained baselines, including MEM1, MemAgent and Memory-R1 (Table~\ref{tab:memr2}). Most of the gain comes from training the memory module rather than the answer agent, and replacing LoGo-GRPO with plain GRPO costs about 3~F1. The authors also report zero-shot gains over the base model on LongMemEval, MSC-Self-Instruct and MemBench~\citep{tan2025membench}, and transfer from 3B to 7B with the largest gains on the smaller model\unverified. Like Mem-T and tree-based CA, LoGo-GRPO obtains per-step baselines by \emph{branching from a shared state}, the idea behind VinePPO and Tree-GRPO; its contribution is branching at the level of sessions and memory states while keeping a global end-to-end term.

\subsection{Critical assessment}\label{sec:memory-critique}
We pose these as open questions rather than verdicts; the full paper, which we could not read, may answer some of them.
\begin{itemize}
\item \textbf{Resettability.} LoGo-GRPO assumes the memory bank can be snapshotted and restored exactly. That holds for a text store, not for environments with side effects (email, file systems, the live web). How should a fair local baseline be built without exact reset, \eg via learned state abstractions or GiGPO-style anchors (Section~\ref{sec:tax-gigpo})?
\item \textbf{Matched compute.} The 3-point gain over GRPO comes with an unreported number of extra rollouts, and extra rollouts alone could produce gains of this size: in the ToolCredit study (Section~\ref{sec:toolcredit}), a variant using 2.53$\times$ the rollouts of its GRPO baseline gained +5.13 points at its endpoint but none at matched compute. The missing baseline is GRPO with the same number of session executions and tokens.
\item \textbf{Scale of the evidence.} With two training conversations and a ten-conversation benchmark, seeds do not substitute for conversation diversity; confidence intervals should be conversation-level. LoCoMo's answer-key errors can add noise comparable to a 3-point effect.
\item \textbf{Judge sensitivity.} Uni-Mem re-evaluated released RL-memory checkpoints with a Mem0-aligned judge prompt and reports outperforming the strongest of them~\citep{unimem2026}, suggesting that J scores are not comparable across papers.
\item \textbf{A stronger evaluation} would add rollout-matched GRPO and full-context baselines, LongMemEval and MemoryAgentBench as primary benchmarks, several judges, and a measured reduction in advantage variance showing that the local term fixes the problem it targets.
\end{itemize}

\paragraph{The authors' research direction}
Memory-R1/R2 come from the group of Volker Tresp and Yunpu Ma (LMU Munich/MCML\unverified), whose 2026 papers point toward \emph{self-improving agents}: memory RL, reasoning compression via mixed-policy distillation~\citep{yang2026reasoning}, and meta-skill evolution on a frozen backbone~\citep{wang2026metaskill}. Ideas joining memory credit with skill or experience evolution sit close to this line (Section~\ref{sec:agenda}).
