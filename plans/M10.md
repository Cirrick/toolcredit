## 1. 目标与范围

E3 全部 200 step 的离线统计：按真正进入 GRPO advantage 的标量 `score` 计，零方差 group 均值 44.07%，
最后 25 step 约 52.75%，历史最低单步 informative 39.06%。这些 group 的 advantage 全为 0，消耗 rollout
算力却不贡献 policy gradient；且比例随训练上升（题目被学会后变全对）。

**机制补正（v2）**：零优势只使 GRPO 的 policy-gradient 项为零。这些序列仍进入 (i) actor 的 KL loss 项
（`kl_loss_coef=0.001`，low_var_kl），(ii) `token-mean` 聚合的分母。过滤把它们从两处一起拿掉：去掉了对梯度
量级的稀释（等价于一个随零方差比例上升而悄悄下降的学习率），同时改变 PG 与 KL 的相对权重和训练分布。
E7 与 E3 的差异因此不只是"多了有梯度的组"，报告时须按此表述；KL 曲线对照见 §4。

M10 只回答一个问题：**在 E3 配方不变的前提下，丢弃 `std(score)=0` 的 group 并用同一 actor snapshot 补采样到
64 个 informative group，是否提高每个有效 update 的学习效率、每单位 rollout 算力的学习效率，以及终点准确率？**

范围内：trainer adapter 实现（按 §6 边界）、CPU fixtures、5-step smoke、200 有效 step 正式 run（4 段）、协议 bump 到
v6 新增两个 role、与 E3 的配对分析、文档；随 run 定位匿名内存泄漏进程（只诊断，不修）。

范围外：改 reward、mask、advantage、优化器任何项；与 E5-v2 组合（另立计划）；额外 seed；改 E3 canonical；
修泄漏；按需缩小补采样批。对照臂为 E3 TIR；M9 NoTool 的零方差统计（44.6%→56.3%）只作旁证。

## 2. 预期与为什么值得跑

结果大体可预期，价值在于把已有诊断数字变成可引用的曲线，并给出 compute-normalized 的诚实比较。
DAPO 原文的学习曲线横轴是训练步数，只用一句话说明总时间没有显著增加，没有给出按算力归一化的曲线；
本计划补这个空档。

| 视角 | 预期 | 理由 |
|---|---|---|
| 按有效 step 的曲线 | E7 早期更快（每步 64 个 informative 组 vs E3 约 36 个） | 有效梯度样本约 1.8× |
| 按累计 rollout 轨迹数的曲线 | E7 与 E3 接近或略差 | 补采样的 rollout 不是免费的 |
| 等算力 checkpoint vs E3 step-200 | 持平（CI 跨 0） | 同样 102,400 条轨迹 |
| 终点（200 有效 step） | 持平或略高（+0–3pt） | E3 已收敛区间，训练量差异不大 |
| 数据难度漂移 | E7 的 informative 集合向 mixed 题集中，后期补采样批次增多 | 全对题被自动跳过；只描述，不作判据 |

**必须同时报告两种 x 轴与等算力配对**，否则会把"多花 2–2.7 倍 rollout"写成"算法更快"。

**补采样成本（v2 重算）**：每个有效 update 整批采 64 题×8，surplus 丢弃、不跨 snapshot 回收。以 E3 informative
比例 .5593（早期）/.4725（后期）作独立同分布二项近似，最多 4 批时期望批数约 2.08 / 2.70（预算推算，非 E7 实测）。
E3 实测单步 161 s 中生成约 55 s、判分约 3 s；E7 只有生成与判分随批数放大，old-log-prob/ref/update 只对选中的 64 组做，
故单步约 224–260 s（1.4–1.6×）。

## 3. 冻结语义

### 3.1 过滤规则

- 单位是 UID（同一 prompt 的 8 条 rollout）；
- 零方差判定用实际标量 `score`（answer + 0.1 format），数值容差 `max − min < 1e-8` 且 `std < 1e-8` 双重检查；
  **不按 `acc` 全对/全错判**（约 7.38% 的 group `acc` 一致但 `score` 有 format 方差，仍有梯度）；
- 每个 generation chunk 取 64 个新 prompt × 8 rollout，与 E3 单步完全相同（整批采，不按需缩批）；
- 一个有效 update 最多 4 个 chunk（首批 + 最多补 3 批）；按采样顺序取前 64 个 informative group 组成 actor batch；
- 多出的 informative group 作为 surplus 存证据，**不跨 actor snapshot 回收**；零方差 group 存证据，不训练；
- 4 批仍不足 64 个 informative group：在 actor update 前显式失败并保存当步全部候选，不做 underfilled update；
- 同一有效 update 的全部候选由同一冻结 actor 生成；补采样期间不调 `_update_actor()`、不同步权重；
- 每个有效 update 恰好一次 `on_batch_end(selected_batch)`、一次 actor update。

### 3.2 与 E3 严格不变的项

起点、数据、reward 函数与 `score` 口径、loss mask、old/ref log prob、GRPO 优势（norm-by-std）、optimizer、
KL/clip、validation cadence（有效 step 0/25/…/200）、`max_actor_ckpt_to_keep=3`、seed。

resolved-config diff gate：E3 → E7 只允许 `algorithm.filter_groups.{enable,metric,max_num_gen_batches}`、
trainer class 标记、`project_name`、`experiment_name`，以及**三条纯基础设施差异**
`actor_rollout_ref.actor.fsdp_config.{param_offload,optimizer_offload}=false`、
`actor_rollout_ref.ref.fsdp_config.param_offload=false` 不同。后三条已由
`rl/runs/e3_offload_check_20260909_150849` 验证：formal 形状 5 步 prompt 与 E3 逐步相同，score/loss/KL 在 E3 步间波动内，
GPU max_allocated 43.5 GB 相同、无 OOM；报告中标注"不影响数值，速度可比性受限（gen 阶段 5 步样本偏慢 10–30%，未定论）"。

### 3.3 Ledger（每个有效 update 一行，随 checkpoint 序列化）

`effective_step`、`generation_batches_used`、`prompts_sampled`、`trajectories_sampled`、`rollout_tokens`、
`informative_groups`、`zero_std_groups`、`surplus_groups`、`all_correct/all_wrong/mixed`（acc 口径，仅描述）、
`generation_wall_time`、`filter_wall_time`、累计值（含 `cumulative_trajectories`）、`equal_compute_checkpoint`（布尔）。
checkpoint 与 ledger 原子写；恢复时 ledger step 不符即失败。

### 3.4 等算力 checkpoint（v2 新增）

`cumulative_trajectories` 首次 ≥ 102,400（E3 全部 200 步的轨迹总数 = 200×64×8）时，该有效 step 结束后额外保存一次
checkpoint 到 `checkpoints/equal_compute_step_<N>/`，不参与 `max_actor_ckpt_to_keep` 轮换，ledger 标记 `equal_compute_checkpoint=true`。
预计落在有效 step 75–95。恰好落在 25 的倍数时与常规 checkpoint 内容相同，仍单独保存一份以保证路径固定。

### 3.5 分段恢复（v2 新增）

200 个有效 step 分 4 段（1–50、51–100、101–150、151–200），每段结束后由 launcher 正常退出并用既有 `--resume` 机制续跑；
恢复时跳过起始验证、resolved config 必须逐字相同、ledger step 必须等于 checkpoint step。分段是基础设施措施，
不改变任何数值语义（optimizer/RNG/dataloader/ledger 均从 checkpoint 恢复）。若第一段实测匿名内存斜率明显低于
0.5 GB/有效 step，后续段长可放宽到 100，记入 §12。

## 4. 训练侧指标与门禁

- fixed-100 greedy 曲线 × 两种 x 轴（有效 step；累计 rollout 轨迹数），E3 同图；
- 每步 `generation_batches_used` 分布；若连续 10 个有效 step 用满 4 批，**暂停并报告**（数据池 informative 题接近耗尽的信号）；

- underfilled 失败即停，不放宽上限；
- 容器内存：memwatch 60 s 一次，记录 cgroup anon/shmem/file 与按进程的 `Pss_Anon` 增量（修复 `step` 字段读取），
  anon 超过 110 GiB 即在下一个 checkpoint 处提前分段；run 结束给出增长进程排名（诊断产物，不修）。

## 9. 预注册解读矩阵（v2）

两个主判据：

- **Δ_step**：fixed-100 greedy 曲线按有效 step 的 0–200 归一化 AUC 之差（E7 − E3），验证点 0/25/…/200 直接对齐；
- **Δ_compute**：M7-panel greedy FULL760 上 E7 等算力 checkpoint（§3.4）与 E3 step-200 的配对 Δ（E7 − E3）与 bootstrap CI。

"正"= Δ ≥ +2pt 且 95% CI 不跨 0；"负"= Δ ≤ −2pt 且 CI 不跨 0；其余为"持平"。Δ_step 的 CI 用验证点上的 bootstrap 近似，
若无法构造则只用 2pt 阈值并写明。

| 情形 | Δ_step | Δ_compute | 写法 |
|---|---|---|---|
| A（预期最可能） | 正 | 持平 | "过滤把无梯度组的算力换成了更多 informative 组，每步样本效率提高约 x，但每单位 rollout 算力没有免费午餐" |
| B | 正 | 正 | "过滤本身有净收益：同样 102,400 条轨迹下 E7 更准" |
| C | 持平 | 持平 | "E3 的 44% 零方差组对学习曲线影响有限；未检出差异（CI 跨 0 ≠ 无影响）" |
| D | 任意 | 负 | "补采样引入的难度漂移抵消了样本效率，等算力下反而更差" |

其余组合（如 Δ_step 负而 Δ_compute 持平）按最接近的一格写并注明。

附报（不参与落格）：按累计轨迹数的 AUC（共同区间 [0, 102,400]，验证点在轨迹数轴上线性插值后积分并除以区间长度）；
rollout token 数与 wall-clock 两条次级算力轴；step-200 终点配对 Δ；每有效 step 平均批数、总轨迹数（与 E3 102,400 对照）；
informative 集合的 level / mixed 比例漂移（描述性）。
