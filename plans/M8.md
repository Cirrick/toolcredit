## 1. 目标与范围

M6 的 E5 v1 没有干净地回答研究问题。它的修正项 `β(s_t − s̄_t)` 在轨迹内不守恒，等价于在 advantage 里
加入了一个"成功且被引用的工具调用"的隐式稠密奖励；策略最大化了这个隐式奖励（4-call 占比训练
2.71%→44.05%、M7 评测 1.3%→92.9%），而终点准确率无收益（M7 FULL760 greedy Δ −1.05pt，95% CI
`[−3.68, +1.58]`）。因此 v1 测的是"隐式 shaping 值不值"，不是"轨迹内信用再分配值不值"。

M8 只回答一个问题：**在轨迹总信用与 E3 严格相同的前提下，把 outcome 信用在同一轨迹的多次工具调用之间
按 `s_t` 重新分配，是否改善学习效率、最终性能或工具行为？**

范围内：一条 200-step 正式 run（E5-v2）、一次 5-step smoke、离线反事实验证、M7 协议 version bump 后对
E5-v2 的统一评测、与 E3/E5-v1 的配对分析、文档更新。

范围外（本计划明确不做）：β sweep、额外 seed、Tier B/GiGPO、E7、修改 E3 failure case 的推理协议、
重跑或改写 E3/E4/E5-v1/E6/M7 任何 canonical 产物。

## 2. v1 失效机制（已有证据，本计划的动机）

三条证据全部来自 E5 v1 正式 run `rl/runs/e5_turn_credit_20260823_082012/` 的 ledger，
2026-09-04 会话即席统计，详见 `reports/qa_log.md` Q12：

| 证据 | 数据 | 含义 |
|---|---|---|
| no-tool turn 被罚 | 102,141 个 no-tool turn 中 33,663 个拿到负修正 | 位置对齐把"没调用"当成"调用得差" |
| 净修正随调用数单调 | step 200 按 0/1/2/3/4 次调用的平均净修正 −0.41/−0.47/−0.23/−0.05/+0.01；token 加权 shift 与调用数相关系数 0.53 | 修正项是隐式奖励，形成"早停即受罚"的自增强 |
| 零方差组里是唯一梯度 | 组内 `score` 零方差比例 step 1 为 25%，step 200 为 48%；这些组 `A_traj=0` | 约半数 batch 在做与 outcome 无关的"多调用"优化 |

设计结论：信用分配必须守恒。E5-v2 的判定标准是**每条轨迹的 token 加权平均优势与 E3 逐条相同，只有
轮次间分布可以不同**。

## 3. E5-v2 冻结语义

### 3.1 公式

对一条轨迹，记 tool turn 集合 `T`（该 assistant turn 解析出恰好 1 个工具调用，与 v1 的
`parsed_call_count == 1` 定义相同）；`n_t` 为第 t 轮 policy token 数；`s_t ∈ {0,1}` 按 §3.2 定义。

```
若 |T| ≥ 2 且组内 std(score) > 0：
    s̃   = Σ_{t∈T} s_t · n_t / Σ_{t∈T} n_t          # 轨迹内 token 加权均值
    c_t  = β (s_t − s̃)        for t ∈ T
    c_t  = 0                  for t ∉ T             # final / no-tool / parser-error / 多调用 turn
否则：
    c_t  = 0                  for all t
A_turn(t) = A_traj + c_t ；   β = 0.5（沿用 v1，不调）
```

性质（均须有断言与 fixture）：

- **守恒**：`Σ_{t} c_t · n_t = 0` 对每条轨迹精确成立（浮点容差 1e-6）；
- **E3 identity**：`|T| < 2`、组内零方差、或所有 `s_t` 相同的轨迹，advantage 张量与 native GRPO 逐元素相同；
- **mask 不变**：tool return 与 padding 的 advantage 恒为 0；
- **组内位置基线 `s̄_t` 不再使用**。它是 v1 位置对齐混淆的来源，去掉是有意的。

### 3.2 `s_t` 定义（v1 adoption heuristic + 两个新增必要条件）

`s_t = 1` 当且仅当以下全部成立：

1. 调用成功执行（v1 `execution_success == 1`，定义不变）；
2. 可见结果被后文采纳（v1 `classify_adoption` 判定 `adopted`，`toolcredit_adoption_v1` 不改）；
3. **新增 · 非重复**：该轮代码经 AST 归一化后的哈希在本轨迹此前的 tool turn 中未出现；归一化函数复用
   `rl/analyze_e4.py:normalize_code`（与预算诊断 `eval/budget_diagnostic.py` 同一口径），不新写；
4. **新增 · boxed 之前**：本轮之前的任何 assistant 文本中不含 `\boxed{`。

ledger 新增字段：`adoption_version = toolcredit_adoption_v2`、`repeat_of_turn`（int | null）、
`after_boxed`（bool）、`s_t_v1`（保留 v1 判定，供审计对比）。`s_t` 即 v2 判定。

### 3.3 门控口径

组内方差以真正进入 GRPO advantage 的标量 `score`（answer + format）计算，与 E7 设计审查及
`reports/docs/grpo_failure_diagnostic_session_summary.md` §8 的 informative-group 口径一致。不按 accuracy 全对/全错判。

### 3.4 记录在案但本轮不跑的变体

`c_t = β·|A_traj|·(s_t − s̃)`（用 |A_traj| 缩放代替硬门控，自动覆盖零方差且消除 β 与 A_traj 量级不匹配）。
不在本轮实现；如 v2 结果为 null 且 exposure 充足，可作为后续独立计划。

## 4. 离线反事实（已于 2026-09-04 会话即席完成，正式版在 §8 步骤 0 重做）

用 E5 v1 的 train ledger（含 `s_t`、span、`A_traj`、`score`）套用 §3 公式，不动 GPU：

| 轨迹窗口 | informative group 比例 | ≥2 次调用轨迹比例 | 收到非零修正（不门控） | 收到非零修正（v2 全条件） | 逐轨迹 token 加权修正和 |
|---|---:|---:|---:|---:|---:|
| step 1–25（接近 SFT 起点） | 73.4% | 31.4% | 17.5% | **14.6%** | 0（精确） |
| step 176–200（v1 过度调用后） | 45.7% | 98.9% | 94.8% | 42.3% | 0（精确） |

判读：v2 正式 run 从 SFT 起点出发，treatment exposure 预计在 **15% 左右**，远低于 v1 的 88%。这是正确的
（信用分配只在"有多次调用可区分"时有意义），但也意味着统计功效有限。**预注册规则：若正式 run 前 25 step
的 exposure < 8%，null result 只能写成"exposure 不足、未检验"，不得写成"方法无效"。**

即席脚本未落盘；步骤 0 必须把它实现为 `analysis/e5v2_offline_counterfactual.py` 并带测试，输出 JSON 后
方可进入实现。

## 9. 预注册预期与解读矩阵

### 9.1 行为指标（必要条件，不是结论）

| 训练轨迹指标（后 25 step 均值） | E3 | E5-v1 | v2 通过线 |
|---|---:|---:|---:|

| 4-call 占比 | 2.7% | 44.1% | ≤ 6% |
| repeated-code 轨迹 | 2.0% | 39.7% | ≤ 4% |
| 训练截断率 | 1.7% | 3.4% | ≤ 3% |
| M7 评测截断率（greedy FULL760） | 9.6% | 100% | ≤ 15% |

任何一项不达线，准确率结果**不解读**，先做机制审计（复用 M6 30 条 mixed-quality 审计流程）。

### 9.2 准确率结果的三种预注册解读

| 情形 | 判据（M7 FULL760 greedy，E3→E5-v2 配对 bootstrap） | 写法 |
|---|---|---|
| A. 无差异（预期最可能） | Δ CI 跨 0 且 fixed-100 early AUC 差 < 2pt | "≤4 轮 horizon 下组内 outcome 方差已足够，轨迹内再分配不增加信息"；干净否定结论。同时说明 v1 的早期 +3pt 很可能来自 over-calling 本身 |
| B. 早期更快、终点持平 | fixed-100 0–100 AUC ≥ +2pt，终点 Δ CI 跨 0，行为达线 | "再分配提高样本效率、不改变能力上限"；正面但有界 |
| C. 终点提升 | Δ 点估计 ≥ +2pt 且 CI 不跨 0 | 必须用逐题迁移矩阵证明增益集中在 ≥2 次调用或含错误恢复的轨迹，否则不归因于信用分配 |

exposure 条款（§4）优先于本表：exposure < 8% 时 A 只能写"未检验"。
