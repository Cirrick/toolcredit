# M2 — 沙箱加固、verifier 与 loss masking 单元测试

状态：**验收通过**（2026-07-14，tag `m2`）｜时间盒 2 天（PLAN §6，Day 4–6），实际 1 天内完成

## 批准的计划（2026-07-14，原文，不追改）

**目标（PLAN §6）**：把 reward 通路的三个可靠性地基打牢。这三件事分别对应 RL 训练中三类
最隐蔽的失败：沙箱被恶意/失控代码搞挂（训练中断）、verifier 误判（reward 直接错，
假阳性 = hacking 入口）、masking 错误（模型学复读环境输出，E6 就是演示这个）。

### 1. 沙箱加固 `env/sandbox.py`（接口 `run_python` 不变，M1 调用方零改动）

- **资源限制**（`resource.setrlimit` 于子进程 preexec）：内存 RLIMIT_AS 1GB、
  进程数 RLIMIT_NPROC（防 fork 炸弹）、文件大小 RLIMIT_FSIZE、CPU 时间；
  超时 5s + 进程组整体清杀（防孤儿进程）。
- **隔离**：子进程 cwd 指向一次性 tmp 目录（写白名单）、清理环境变量；**禁网**优先尝试
  `unshare -n`（无 root 的 pod 上 user namespace 可能被禁，执行时探测）——若平台不支持，
  如实记录差距，不死磕（面试答案本来就是"工业级用 container/gVisor，我说明差距"）。
- **`env/test_sandbox.py`**（PLAN 指定用例全覆盖）：正常计算 / 死循环超时 / fork 炸弹 /
  `import os` 删文件企图（验证项目目录无恙）/ 内存炸弹 / 超长输出截断 2k / stderr 捕获。
- 集成 M1 的 AST 版 auto-print（单一来源）。

### 2. Verifier `rewards/verifier.py` + 200 例人工审计

- fallback 链：math-verify → sympy 规范化 → 字符串精确匹配；返回 `{correct, method, error}`，
  任何失败记日志计入 invalid（禁止事项 #2）。
- `rewards/test_rewards.py`：等价 case（分数/根式/坐标对/区间/π 表达/百分数/前导负号）
  + 不等价 case + 提取失败 case。
- **审计**：从 M1 probe 的 4000 条真实轨迹抽 200 个（模型输出, 标答）对，verifier 判定后
  先逐例粗核，产出审计表（假阳性/假阴性率 + 典型误判例），存疑项列给用户抽检。
  报告 02 附录素材，直接回答"假阳性和假阴性哪个对 RL 危害更大"。

### 3. 复合奖励 `rewards/composite_reward.py`

`r = 1.0·answer_correct + 0.1·format_ok + λ_exec·frac_tool_success − λ_budget·max(0, n_calls−budget)`，
λ 默认 0（E4 才开）；format_ok = boxed 存在且工具调用可解析。带测试。
训练 reward 口径严格只认 `\boxed{}`（反 hacking：防"多写候选数字撞答案"）。

### 4. Loss masking 单元测试（本项目最重要的单元测试）

- 目标已定位：`verl/experimental/agent_loop/tool_agent_loop.py` 的 `ToolAgentLoop`
  （delta-based tokenization，生成段 mask=1、工具返回段 mask=0）。
- 构造含 **2 次工具调用**的假轨迹（真 tokenizer Qwen3-1.7B 本地已有，不需要 GPU/server，
  mock 掉生成后端），断言：prompt token、工具返回 token、padding 的 mask 全为 0；
  模型生成 token 全为 1；截断场景 mask 长度对齐。
- 测试放 `rl/custom/test_masking.py`——只测不改 verl；若发现 mask 有 bug 则按禁止事项 #3
  先向用户报告。

### 风险与预案

- unprivileged userns 被禁 → 禁网降级为"记录差距"（不影响验收，资源限制版已够训练用）；
- math-verify 的 signal 超时机制与 pytest 的兼容性 → 若冲突改子进程判分；
- ToolAgentLoop 依赖注入太深不好单测 → 退一步测其可独立调用的内部方法 + 用 M0 真实
  rollout 落盘数据做一次端到端 mask 断言（两条路都能满足验收）。

### 不做的事

不写 RL config（M4）；不做 SFT 数据生成（M3）；不给沙箱上容器方案（超出预算，记差距即可）。

## 执行偏差与决策记录

| 事项 | 计划 | 实际 |
|---|---|---|
| 禁网 | 预判 userns 可能被禁，备降级 | 实测 `unshare --map-root-user -n` 可用 → **禁网真实现**（fresh netns，连外网即失败），有对应测试 |
| 禁写 | 白名单 tmp | cwd/HOME/TMPDIR 指向一次性 tmp + RLIMIT_FSIZE 16MB；同 uid 绝对路径删改**不可挡**（无 mount ns remount 权限）→ 记录为已知差距并用测试钉住该行为 |
| 审计发现 | 只审 verifier | 审计顺带发现 **M1 probe 判分 2 处假阴性**（`20\%` 类 gold）→ probe 判分统一切换到 rewards/verifier 并全量重算：各 level ≤1pt 变化、结论不变（报告 01 已更新，含"全部"行工具报错率誊写错误修正 0.383→0.344） |
| verifier 口径 | 训练严格 boxed | 实现为 `strict_boxed` 参数双口径（训练严格/评测宽松），审计对两口径同时跑 |
| 审计工具 | 审计动作 | 落成可复现脚本 `rewards/audit_verifier.py` + 明细 `data/verifier_audit.jsonl` |
| masking 测试 | 预案一（mock 后端驱动真实状态机） | 走通：`__new__` 绕过 DI，真 tokenizer/hermes parser/FunctionTool + FakeServer；**未发现 verl mask bug**（不触发禁止事项 #3）。附带发现值得记录的契约：verl 用 `tokenizer.pad` 填充 mask（填的是 pad_token_id 而非 0），靠乘 response attention mask 归零——padding 测试钉住此契约 |
