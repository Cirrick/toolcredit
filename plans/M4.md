## 批准的计划（2026-07-14，原文，不追改）

**目标**：从 SFT-6k 起点（`sft/checkpoints/qwen3-1.7b-sft`），把 E3（标准 GRPO，
轨迹级优势广播）训稳——它是 E4/E5/E6 全部对照的基准。

### 0. 前置装配（半天）

- 数据：`train_subset.jsonl` 减去 held-out → 5203 题转 verl parquet（沿用 M0 数据格式：
  prompt+指令后缀、reward_model.ground_truth）；val = MATH500 抽 100 题固定子集
  （test_freq 用，全量 500 留 M7）。
- 工具：训练用 SandboxTool 改为**调用我们的 `env/sandbox.py` + `prepare_tool_code`**
  （替换官方教程沙箱的行版启发式与无限制执行），放 `rl/custom/`。
- reward：`rewards/composite_reward` 经 verl `custom_reward_function` 配置注入
  （严格 boxed 口径）——确认注入点后记 `rl/custom/CHANGES.md`（禁止事项 #1/#2）。

### 1. 配置 `rl/configs/e3_grpo_baseline.yaml`（PLAN §8.1 骨架 × M0 实测校正）

关键字段：GRPO、train_batch_size 64 × rollout.n 8、lr 1e-6、use_kl_loss + KL coef 0.001、
clip_ratio 0.2/0.28（DAPO clip-higher 防熵坍缩）、multi_turn max_turns 4、
max_response_length 3072、total_training_steps 200、save/test freq 25、
logger tensorboard（W&B 若用户提供 key 则加）。字段名以 verl 0.8.0 实际 schema 为准，
对照 M0 官方示例校正。

### 2. 冒烟与长跑

- 先 5-step 冒烟（复用 M0 流程验证新工具/reward 接线，val 前后各一次）；
- 正式 200 step tmux 长跑（预计 1.5–2.5 GPU 日）：监控 PLAN §8.2 十项指标
  （reward/mean、pass@1(eval)、kl、entropy、response_length、n_tool_calls、
  tool_error_rate、invalid_format_rate、group_all_correct/wrong_frac），
  异常处置手册写进 README；**重点盯 M0 遗留的 DataLoader worker 被杀问题与 NFS ckpt IO**。

### 3. 验收（PLAN §8）

- 全部曲线无病态形状（熵坍缩 <0.3 / KL 飙升 / 长度爆炸）；
- 产出该 run 的一页训练日志摘要 + 五件套落盘。
- 超预算 50% 触发 PLAN §12.2 降级（1.5B 已是现状 → max_turns 3 / resp 2048 重试；
  仍不稳则以"已诊断的不稳定 + 处置记录"形态入报告）。
