## 0. 术语

- **TIR**（tool-integrated reasoning）：prompt 的 chat template 注入 `code_interpreter` schema，模型在文字推理中可发起
  Python 调用。项目内 raw/SFT/E3/E5-v1/E5-v2 的训练与评测全部是 TIR。
- **NoTool**：同一模型、同一 user 消息，chat template **不传 tools**。模型仍做逐步文字推理（即通常所说的 CoT），只是
  没有解释器可调。M1 探针与 M3 复测中的"CoT 臂"就是这个设置；本计划统一改称 NoTool，避免与 Qwen3 的 thinking 模式
  混淆——所有臂都保持 `enable_thinking=false`。
- 两种模式的**唯一差别是 prompt 里有没有工具 schema**，以及随之而来的 agent loop（多轮工具循环 vs 单轮生成）。

## 1. 目标与范围

项目目前所有 RL 结果都在 TIR 协议下取得：SFT→E3 的 +12.76pt（greedy FULL760，95% CI `[+9.74,+15.92]`）里，
多少来自"学会用工具"、多少来自"RL 本身提升数学推理"，现有证据分不开。`analysis/tool_use_conditional_accuracy.json`
只给出相关性（E3 有调用轨迹 .774 vs 零调用 .619），且策略自选调用与否，两组题不可比。

M9 只回答一个问题：**在同一 SFT 起点、同一数据、同一 GRPO 配方、同一训练量下，去掉工具后 RL 能达到的终点与
学习曲线，相比 E3（有工具）差多少？** 这是"工具学习是否提高准确率"的因果对照，也是面试必问项。

附带回答（只用评测、不训练）：带工具训出来的 E3 权重，拿掉工具后还剩多少推理能力；带工具的 RL 是提升了模型自身
推理，还是只学会了把计算外包给解释器。

范围内：一条 200-step 正式 run（E3-NoTool）、一次 5-step smoke、评测协议 bump 到 v5、四个 NoTool 评测角色
（raw、SFT、E3、E3-NoTool 各在无工具模式下评测）、配对分析、文档更新。

范围外：改 E3 任何 canonical 产物；调 E3-NoTool 的超参使其"公平"（唯一变量是工具）；CoT-SFT 起点（§2.2 备选，
本轮不做）；额外 seed；E7；任何 turn credit 变体；E3-NoTool 权重的有工具评测（RL 阶段从未见过 schema，无解释意义）。

## 2. 设计：唯一变量是"有没有工具"

| 项 | E3（已有） | E3-NoTool（本计划） |
|---|---|---|
| 起点 | `sft/checkpoints/qwen3-1.7b-sft`（SHA256 `cb5f43da…7cb5`） | 相同 |
| 数据 | `rl/data/e3_train.parquet` 5203 条、`e3_val_math500_100.parquet` 100 条，hash 相同 | 相同 |
| 提示 | user 消息 + chat template 注入 `code_interpreter` schema（hermes） | user 消息，**chat template 不传 tools**；不加 system prompt、不加"请逐步推理"指令（与 M1 探针的无工具臂一致） |
| agent loop | `toolcredit_agent`（ToolAgentLoop 子类），`multi_turn.enable=true`、4 tool turns + 1 final | veRL 原生 `single_turn_agent`，`multi_turn.enable=false` |
| 生成预算 | 3072 response tokens（多轮累计） | 3072 response tokens（单轮） |
| reward | `rl/custom/reward.py:compute_score`：answer + 0.1 format，shaping 全 0 | 相同函数；tool 计数字段缺省为 0，`format_ok` 退化为 boxed 判定 |
| GRPO | 64 prompts × 8、T=1.0、lr 1e-6、KL 0.001、clip 0.2/0.28、200 step、save/test freq 25、`max_actor_ckpt_to_keep=3` | 相同 |
| seed | resolved config 同值 | 相同 |
| loss mask | tool return token mask=0 | 无 tool token，mask 恒为响应全 1（无操作） |

resolved-config 结构 diff gate：E3 → E3-NoTool 只允许 `rollout.multi_turn.enable`、`rollout.agent.default_agent_loop`、
`rollout.agent.agent_loop_config_path`、`rollout.multi_turn.*`（因 enable=false 而失效的子字段）、`trainer.project_name`、
`experiment_name` 不同。任何其它字段差异即 fail。

### 2.1 为什么不是"保留 schema 但禁用工具"

保留工具 schema 而让调用失败，测的是"坏掉的工具"，不是"没有工具"。M1 探针的无工具臂就是不传 tools 的纯提示，
E3-NoTool 与之口径一致。

### 2.2 起点公平性：已知方向的偏置，用两个零成本角色量化

SFT 起点由 Qwen3-8B 的 **TIR 轨迹**蒸馏而来。M1/M3 复测显示它的无工具能力从零样本 0.777 回落到 0.736，
即 E3-NoTool 从一个"习惯调工具但拿不到工具"的起点出发，**偏置方向确定：对 NoTool 臂不利**。处理方式：

1. **仍用同一起点**：这是唯一能把"工具"孤立成单变量的做法。结论按保守方向解读——若 E3-NoTool 与 E3 打平，
   "工具无增益"只会被低估；若 E3 胜出，Δ 中可能含起点劣势，必须扣减（见 §8）。
2. **用 `raw_base_model_notool` 与 `sft_start_notool` 两个评测角色直接量出起点欠的债**：SFT-NoTool 比 raw-NoTool
   低多少，就是 TIR-only SFT 对无工具推理造成的损失上界。200 步 on-policy RL 通常会很快洗掉格式习惯，实际残留
   预期远小于该上界；`§4` 的标签吐出率曲线是"是否洗掉"的直接观测。
3. **备选（本轮不做，记录在案）——CoT-SFT 对称起点**：用同一教师 Qwen3-8B、同一训练池、同样五条件拒绝采样，
   蒸馏无工具轨迹并做同规格 LoRA SFT，再从该起点跑 NoTool GRPO。它在"起点模态"上对称，但引入新混淆（教师在两种
   模态下的轨迹质量与覆盖不同），且需重做约 M3 一半的工作量（蒸馏 4–6 h GPU + SFT < 0.5 GPU 日 + 一条 200-step run）。
   **触发条件**：§8 判读落入情形 A，且 SFT-NoTool 比 raw-NoTool 低超过 3pt（起点债务足以解释 Δ 的相当部分）时，
   作为敏感性分析另立计划。

## 3. 评测：协议 v5，只加 NoTool 生成模式与四个角色

v4 的 generation 语义假设每个 role 都用 `code_interpreter` 工具循环。v5 在 v4 的闭包不动的前提下新增：

1. `generation_mode` 字段：`tir`（现有五角色，默认，逐字段等于 v4）与 `notool`（本计划新增）；
2. 四个 `notool` 角色：

   | 角色 | 权重 | 需要训练 | 用途 |
   |---|---|---|---|
   | `raw_base_model_notool` | 原始 Qwen3-1.7B（复用 M7 已验证权重） | 否 | M1 零样本增益在 panel 上的复现；起点债务的参照 |
   | `sft_start_notool` | 现有 SFT checkpoint（复用） | 否 | TIR-only SFT 对无工具推理的代价；E3-NoTool 的真实起点 |
   | `e3_grpo_baseline_step_200_notool` | E3 step-200（复用 M7 物化） | 否 | 同一权重拿掉工具：推理时工具的边际价值；带工具 RL 是否提升了自身推理 |
   | `e3notool_grpo_step_200` | **本计划新训练** | 是 | primary 对照臂 |

3. `notool` 模式的生成：同 panel 760 题、同 greedy/sampled 参数、同 seed 派生、同 3072 token 预算、同 verifier；
   chat template 不传 tools；无 tool turn，`termination_reason ∈ {final_answer, length}`；每行新增
   `tool_tag_emitted`（响应文本中是否出现 `<tool_call>` 或等价 hermes 标签）与 `tool_tag_count`；
4. 语义校验器：证明 v5 除 `generation_mode`、四个角色、其物化与 M9 evaluator 绑定外与 v4 逐字段相同；
   现有五角色的 15,200 + 3,800 条 canonical 轨迹复用（hash 重验），不重新生成。

新增生成量：4 角色 × 760 × (1 + 4) = 15,200 条；单轮无工具等待，预计 3–5 h。

配对（10k source 分层 question-cluster bootstrap，与 M7/M8 同代码）：

| 配对 | 地位 | 回答 |
|---|---|---|
| E3 → E3-NoTool（greedy） | **primary** | 训练与推理都有工具 vs 都没有工具：RL 终点上工具的净贡献 |
| SFT-NoTool → E3-NoTool（greedy） | secondary | 无工具 RL 的增益，与 SFT→E3 +12.76pt 对照 |
| raw-NoTool → SFT-NoTool（greedy） | secondary | TIR-only SFT 对无工具推理的代价（起点债务） |
| E3（TIR）→ E3-NoTool-eval（同权重） | secondary | 推理时工具的边际价值；off-distribution，为 E3 纯推理能力的下界 |
| SFT-NoTool → E3-NoTool-eval | secondary | 带工具 RL 有没有顺带提升无工具推理（"学推理"还是"学外包"） |
| E3-NoTool-eval ↔ E3-NoTool | secondary | 同为无工具推理，用工具训的 vs 不用工具训的 |
| raw-NoTool ↔ raw（TIR） | descriptive | M1 零样本增益在 MATH500/AIME/GSM8K 上的复现 |
| 以上 sampled | exploratory | 按 M7 guardrail 不作因果主张 |

**解释边界**：`sft_start_notool` 与 `e3_grpo_baseline_step_200_notool` 都是 off-distribution 评测（权重从未在无 schema
prompt 下训练），可能按习惯吐出 tool_call 标签被判 invalid。因此二者只作 secondary/descriptive，配对报告必须同时给出
`tool_tag_emitted` 比例；含标签的轨迹不剔除、不修复，只标注。primary 仍是 E3 与 E3-NoTool 各在自己训练模态下的比较。

E3-NoTool 的 taxonomy 只做 deterministic coarse proposal（无 tool 类别自然为空），不做新的 blinded audit。

## 4. 训练侧机制指标（必须记录，不作判读依据）

- fixed-100 greedy 曲线（step 0/25/…/200）与 E3 同图；
- response length、entropy、KL、截断率（3072 token）、boxed 缺失率；

- 无 tool 指标（mean calls 恒 0），launcher 断言训练 JSONL 中 `tool_call_counts` 字段缺省或恒 0。

## 8. 预注册解读矩阵（greedy FULL760，E3 → E3-NoTool 配对 bootstrap；Δ = E3-NoTool − E3）

记 `D_start = acc(raw-NoTool) − acc(SFT-NoTool)`（起点债务上界，greedy FULL760）。

| 情形 | 判据 | 写法 |
|---|---|---|
| A. 工具有净贡献（预期最可能） | Δ ≤ −2pt 且 CI 不跨 0 | "同配方下工具学习提高终点 x pt"；必须 (i) 按 level/source 分解——增益集中在 MATH L4–5 与 AIME 才与 M1"潜在增益在 L4–5"一致，GSM8K 也有增益则标注可能来自格式/截断而非计算；(ii) 报告 `D_start`，写明 Δ 的量级中最多有 `D_start` 可归于起点劣势；若 `|Δ| ≤ D_start` 则不得写成"工具有净贡献"，只能写"未能与起点劣势区分"，并触发 §2.2 备选的考虑 |
| B. 无差异 | CI 跨 0 | "1.7B、≤4 轮、MATH 训练池下，RL 增益主要是推理能力提升，工具未提供额外准确率"；这是保守方向的结论，起点劣势只会使其更强。同时报告 E3-NoTool 的截断率与 verbal loop 比例（E3 预算诊断已见 34/38 零工具截断为语言循环） |
| C. NoTool 更好 | Δ ≥ +2pt 且 CI 不跨 0 | "工具在此规模下是负担"；必须核对是否由 E3 的 tool-turn 截断（9.6%）驱动，报告去掉截断轨迹后的条件比较作为 secondary |

附加预注册：
- SFT-NoTool → E3-NoTool 的增益若与 SFT→E3 的 +12.76pt 同量级（差 < 3pt），支持 B 的"RL 增益不依赖工具"；
- E3-NoTool-eval 的三组 secondary 比较只写描述，不进入 A/B/C 判据；报告时必须附 `tool_tag_emitted` 比例；
- 不因结果调 E3-NoTool 超参、不追加 seed、不换起点。
