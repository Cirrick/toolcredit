## frozen v2 的复用方式与 M7 runtime binding

### 为什么必须有窄版本 successor

frozen v2 明确要求 E5 在训练前为 `state=future, locator=null`，并规定“未来 diagnostic evaluation 前必须
由后续 protocol version 解析和验证 canonical step-200 role”。因此直接修改
`eval/diagnostic_protocol_v2.json`、在命令行临时覆盖 E5 path，或让 evaluator 自行猜最新 E5 run 都不合规。

后续获得 implementation 授权后，M7 创建 v3 runtime bundle；v3 是 **v2 的 checkpoint/evaluator binding
successor**，不是重设计 diagnostic protocol。预期新增文件为：

```text
eval/diagnostic_freeze_v3_verification.json

```

v3 只允许改变或新增以下 top-level 内容：

- `protocol_version/schema_version/frozen_at/git_head_at_freeze/supersedes`；
- `checkpoints/checkpoint_locator_gate`：把 E5 future/null 解析为上述正式 step-200，并加强四角色 identity；
- `evaluator`：记录统一 evaluator、resolved eval config、pin veRL/SGLang merger、output schema 和 launcher hash；

## evaluator 实现边界

后续 implementation 预计集中在：

```text
eval/checkpoints.py             # role gate、FSDP materialization manifest、export identity
eval/generate.py                # 统一 multi-turn generation与atomic/resume persistence
eval/evaluate.py                # strict verifier、完整 trajectory enrichment、completeness gate
eval/metrics.py                 # pass@k、工具/错误/恢复指标、denominator

scripts/m7/watch_unified_eval.sh
.gitignore                      # 忽略eval/runs/大产物，继续保留frozen panel例外
```

具体实现原则：

1. 复用 veRL 0.8.0 Hermes multi-turn路径、`ToolCreditSandboxTool`、`env/sandbox.py` 和已有结构化
   tool/turn metadata helper；不复制 M1 OpenAI probe 的另一套截断/工具行为。
2. 四个 role使用完全相同的 diagnostic agent loop。可复用 frozen `TurnCreditAgentLoop` 记录 visible
   per-turn/tool/adoption metadata，但 M7不安装 advantage wrapper、不调用 trainer、不计算或应用
   `A_turn`；它在这里仅是 metadata-only evaluator path。
3. `enable_thinking=false`、prompt suffix、SFT chat template、Hermes schema、最多4个 user/tool turn、最多5个
   assistant turn、累计3072 response token、单次parallel call、5秒sandbox timeout和字符级512 middle
   truncation全部由 protocol读取并逐项assert，不在代码中另放一套“近似默认值”。
4. infrastructure错误（server crash、I/O失败、schema写入失败、worker丢失）使 shard失败并可恢复，不能当作
   模型答错；模型产生的 parser/tool/timeout/invalid/truncation必须写入轨迹并计入指标，不能静默重试成
   一个更有利样本。
5. 每条raw trajectory先append到role/setting/source独立的immutable generation shard；strict scoring和taxonomy
   enrichment另写canonical trajectory，不覆盖原始响应。canonical完成前二者通过key/hash双向关联。
6. resume只跳过已经通过schema、hash、seed、role和question验证的exact key；重复key、半行、冲突内容、
   output hash不一致一律停止。中断文件进入run内`recovery/<UTC>/`，不能和canonical shard混用。
7. 不修改site-packages，不fork veRL。若 pin API无法可靠透传per-request seed、共同tokenizer或累计多轮budget，
   停止并向用户展示具体边界；未经专项批准不复制 trainer/rollout大段内部逻辑。
8. 预计不新增依赖；若实际需要新增/变更依赖，先说明必要性并同步更新`requirements.txt`与`environment.md`，
   不只修改conda环境。

## 统一评分与指标

### 性能

- greedy：每题唯一轨迹的strict `pass@1/accuracy`；
- sampled：每题正确数 `c∈[0,4]`，报告
  `pass@k = 1 - C(4-c,k)/C(4,k)` 的 question mean，固定给出 `k=1,2,4`；
- MATH500、AIME2024、AIME2025、GSM8K分别报告exact numerator/denominator；
- full-760 aggregate使用原始source权重 `500/760,30/760,30/760,200/760`，不改成事后equal-source macro；
- GSM8K明确是sanity，不用其较大200题权重掩盖MATH/AIME结论；主表同时展示各source，aggregate不能单独出现；
- invalid、format和truncation属于结果的一部分，不从denominator删除。

### 工具与agent行为

每个role/setting/source至少报告：

```text
mean response tokens
mean tool calls + 0/1/2/3/4-call fractions
no-tool correct / no-tool wrong
per-call execution success
parser / dispatch / sandbox error（分开给numerator）
any-error trajectory rate
error recovery numerator/denominator/rate
repeated-code / trivial-code / unused-or-misread-result
tool overuse
invalid / boxed-format failure
budget exhaustion / truncation
```

错误恢复以每条trajectory的第一个可观察parser/execution error作为anchor：denominator为至少发生一次该类错误的
trajectory，numerator为其最终strict answer正确；同时分别报告parser-only和execution-error denominator，避免
一个合并比例掩盖错误来源。denominator=0报告NA，不用0或伪计数。

greedy与sampled都完整报告，不能选择更有利的一套作为唯一结论。二者不一致时把差异本身写入结论：greedy
描述确定性policy，sampled描述固定温度下的解分布和pass@k，不互相替代。

## Failure taxonomy、盲审与paired transition

### 全量coarse proposal与manual audit分层

`toolcredit_failure_taxonomy_v1` 原样使用。deterministic coarse classifier为全部15,200条轨迹生成proposal和
rationale；这保证完整transition matrix可计算，但自动proposal不冒充人工语义真值。

manual audit packet使用stable hash预注册抽样：每个 `(checkpoint_role, setting)` 从wrong trajectories中最多
抽24条，共最多192条；先平衡四source，再平衡coarse primary label，不按fixed/regressed方向或结果好坏挑例。
若某stratum不足24则审计全部。packet必须checkpoint-blinded，只含question/gold、完整assistant/tool轨迹、
strict verifier事实和裁决所需上下文；role、训练阶段、另一checkpoint结果、transition direction藏在private index。

审计输出必须记录reviewer类型：用户/独立人工才称human audit；Codex/LLM裁决明确标为manual Codex/agent
adjudication，不计作独立human。报告每类分母、uncertain率、auto↔manual confusion/agreement和典型边界。
项目级failure结论必须同时给full-panel coarse exact counts和blind audit支持；audit不支持或分母≤6的类别只报告
观察值并标记evidence insufficient。

### 三个预注册阶段迁移

greedy和sampled分别对以下三对做完整分析：

1. raw→SFT：冷启动具体解决/引入什么；
2. SFT→E3：标准trajectory GRPO具体解决/引入什么；
3. E3→E5：turn-level credit相对标准GRPO的核心直接对照。

每对、每setting、每source及full aggregate必须同时输出：

```text
denominator
failed -> correct (fixed)
correct -> failed (new failure)
correct -> correct
failed -> failed
accuracy delta
primary failure transition matrix（含correct状态）
secondary tag transition
conditional fix rate by source category
new failure rate
failure-category migration rate
exact evidence pointers
```

四格之和必须严格等于pair denominator。greedy denominator为760；sampled pair denominator为3,040，但统计
bootstrap以question为cluster，把同题四个sample index一起重采样，不能把3,040条当独立题。

### Bootstrap

- 10,000次，seed 42，two-sided percentile 95% CI；
- 在MATH500/AIME2024/AIME2025/GSM8K frozen source strata内分别重采样question，并保持原source权重；
- sampled每次抽中question时同时带上该题四个paired sample index；
- 每个replicate重算完整ratio/matrix statistic，不bootstrap已经聚合的rate；
- 报point estimate、lower/upper、effective replicates；零分母为`NA (0 denominator)`，不加pseudocount；
- 不因CI不利而换seed、换denominator、并类或只展示修复。

典型pair展示使用stable hash从fixed/new/unchanged-failed/unchanged-correct分别选例，并覆盖三段迁移；不能只展示
E5修好的题。E3→E5类别结果要与M6既有per-turn mechanism audit通过evidence pointer关联，但不能把M6旧
fixed-100 outcome混入M7 rate。

  50%时停止检查，不通过减少panel、sample数、turn/token budget或跳过role来“完成”。
